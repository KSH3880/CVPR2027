# Bridge 학습 개선안과 우선순위

기록일: 2026-11-12. 대상: `TokenHSI_stage12_teacher_sensor`의 `stage2_sensor_900_cliff_bridge_surface`.

이 문서는 사용자 제안과 코드·로그 분석을 바탕으로 정리한 개선 후보다. 순위는 예상 효과와 구현 위험을 함께 고려한 판단이며, 개선 효과가 실험으로 입증된 것은 아니다. 이번 기록으로 코드·설정·학습 프로세스를 변경하지 않았다. 구현·학습 변경은 별도 요청 후 진행한다.

## 판단 근거

- 앞선 1125–1324 epoch 분석에서 연결 완료 분기의 횡단 지표는 입구 출발 약 39.3%, 중간 출발 97.0%, 후반 출발 98.1%였다. 서로 다른 초기화 분포의 학습 중 종료 통계로, 고정 프로토콜 평가나 최종 과제 성공률은 아니다. 기록을 위해 재평가하지 않았다.
- 현재 일부 연결 완료 샘플은 이미 다리 중간·후반에서 시작한다. 출발 무대에서 다리로 진입하는 경험이 상대적으로 부족하다는 해석이 유력하다.
- 외력·연결 완료 분기에는 이미 길이 샘플링 커리큘럼이 있다. 초기 span 비율 80/15/5%를 1000 update까지 유지하고 이후 2000 update 동안 균등 비율로 바꾼다. spawn 깊이와 목표 거리에는 같은 스케줄이 없다.
- 앞선 분석에서 외력 분기 crosser의 약 41%는 본인 횡단 전에 동료 낙상으로 에피소드가 끝났다. 에이전트 수에 따른 성공 경험 단절도 고려해야 한다.

## 우선순위

| 순위 | 개선안 | 예상 효과 | 구현 가능성과 주요 한계 |
| --- | --- | --- | --- |
| 1 | spawn·목표 거리 커리큘럼 | 높음 | 배치 코드 확장으로 가능. 성공까지의 이동·대기 시간을 줄일 수 있음 |
| 2 | 입구·출구 경계 전환 RSI | 높음 | 가능. 자세·속도·payload·관계 상태를 일관되게 초기화해야 함 |
| 3 | 외력/연결 완료 다리의 접합 틈 축소와 길이 커리큘럼 | 높을 가능성 | 분기별 적용 가능. 협력 PUSH의 삽입 여유와 분리해야 함 |
| 4 | 횡단 인원·관계·도착 지연 커리큘럼 | 중간∼높음 | 총 4명 유지 가능. 최종 분포로 복귀하고 어려운 샘플을 남겨야 함 |
| 5 | 입구→다리→출구 경로 진행 보상 | 중간∼높음 | 가능. 입구·다리 위 체류를 강화하지 않도록 설계해야 함 |
| 6 | 다리 중간·후반 RSI 확대 | 추가 효과 제한적 | 일부 이미 구현됨. 해당 구간 지표가 높아 확대 효율이 낮을 수 있음 |
| 7 | 횡단 완료 후 RSI | 횡단에는 낮음, 후속 과제에는 유용 | 가능. 횡단 지표에서 초기 도착 상태를 분리해야 함 |
| 8 | coordination 일부 동결 해제·sensor 주입 위치 변경 | 불확실 | 기존 협력 지식 손실 위험. 환경 난이도 검증 이후 검토 |
| 9 | 마찰계수 추가 조정 | 단독 효과 낮을 가능성 | 조정 가능하나 상면 1.0 적용 후에도 진입 병목이 남아 있음 |

## 1. 거리 커리큘럼

사용자가 제안한 spawn·목표 거리 warmup을 최우선 후보로 둔다.

1. 연결된 짧은 다리에서 입구 가까이 출발하고, 출구 가까이에 목표를 배치한다.
2. 횡단이 안정되면 출발 거리와 목표 거리를 각각 늘린다.
3. 이후 긴 다리와 늦게 도착하는 다리를 늘린다.

출구 가까운 목표는 횡단 직후 과제 진행 보상을 경험하게 한다. 거리·길이·관계 난이도를 동시에 올리면 실패 원인이 섞이므로 단계별로 조절한다. 4명을 한 지점에 몰지 말고 충돌 없는 간격을 확보한다. 구체적인 거리·비율·전환 기준은 아직 확정하지 않았다.

## 2. 경계 전환 RSI

사용자가 제안한 중간·횡단 완료 초기화는 가능하다. 다만 우선순위는 다리 중앙보다 다음 전환 구간에 둔다.

- 입구 직전에서 다리로 첫발을 내딛기 전.
- 다리에 진입했으나 몸 전체가 올라오지 않은 상태.
- 출구 직전에서 무대로 마지막 발을 옮기기 전.

짧은 성공 구간을 익힌 뒤 출발 위치를 점차 뒤로 이동시키는 방식이 유망하다. 현재 학습 규격과 일치하는 유효한 자세·속도 상태를 사용한다. 운반 중이면 손과 payload의 상대 자세·속도를 맞추고, BEFORE이면 선행 완료·후행 대기 상태도 맞춘다. 사람 위치만 옮기는 초기화는 피한다.

중간·후반 RSI의 대폭 확대는 우선하지 않는다. 횡단 완료 후 초기화는 SIT·운반·BEFORE 후속 수행을 위한 보조 샘플로 검토한다. 두 초기화만 늘리면 출발 측에서 다리를 기다리고 진입하는 경험이 줄어들 수 있다.

## 3. gap 길이와 접합 틈

무대 간 gap 길이와 다리 끝 접합 틈은 별도 변수다. 앞선 코드 비교에서 중앙 정렬 시 접합 틈은 현재 양 끝 각각 약 10cm, Square Sensor는 약 1cm였다. 유력한 난이도 차이지만 단독 효과는 아직 검증하지 않았다.

- 외력·연결 완료 분기에서 Square에 가까운 틈으로 시작하는 비교를 우선 검토한다.
- 협력 PUSH에 같은 축소를 일괄 적용하면 상자가 끼는 문제가 재발할 수 있으므로 삽입 여유를 분리한다.
- gap 길이를 바꿀 때 대응 다리 길이도 함께 맞춘다. gap만 바꾸어 겹침과 접합 틈까지 바뀌지 않게 한다.
- 협력 PUSH의 기존 인원별 상자 규격·파지 규약을 임의로 축소하지 않는다.

## 4. 횡단 인원·관계·도착 지연

총 4명은 유지하되 횡단 담당을 2→3→4명으로 늘리는 방법을 검토한다. 초기 나머지 인원은 안전한 위치에서 기존 과제를 수행하게 한다. 이는 개별 종료·reset 체계를 바꾸는 것보다 수정 범위가 작다.

BEFORE와 긴 다리 도착 지연은 쉬운 횡단이 확보된 뒤 늘리고, 기존 지식 유지를 위한 샘플과 일부 어려운 샘플을 계속 남긴다. 기다렸다가 재출발하는 능력은 다리가 없는 출발 측에서 경험해야 하므로, 짧은 도착 지연부터 현재의 긴 범위로 확장한다. 연결 완료·중간 RSI만으로 대기 능력을 충분히 학습한다고 가정하지 않는다.

## 비교와 적용 원칙

- 거리 커리큘럼과 경계 RSI를 우선 분리 비교하고, 이후 조합 효과를 확인한다. 한 번에 모든 후보를 바꾸지 않는다.
- 비교 checkpoint·epoch/샘플 예산·시나리오 분포·분모를 명시한다.
- 원래 출발 무대에서 실제로 건넌 비율을 핵심 지표로 삼는다. 중간·후반·도착 후 초기화를 별도 집계하고 초기 상태를 횡단 성공으로 계산하지 않는다.
- 횡단, 본인 낙상, 동료 낙상에 의한 중단, 시간 초과, 최종 과제 완료를 구분한다.
- 기존 variant와 추론 재사용성을 보존한다. 학습 중단이 필요하면 대상 서비스·PID·cwd·config·MPS 연결을 확인하고 해당 client만 중단한다.
- 현재 상면 마찰 1.0·고정 신체 관측 높이와 동결 규칙을 비교 기준으로 삼는다. 동결 해제·sensor 위치·추가 마찰 변경은 앞선 후보를 검증한 뒤 검토한다.
