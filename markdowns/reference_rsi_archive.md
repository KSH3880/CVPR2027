## 사용자 목표와 우선순위

**박스 크기를 최대한 유지하면서, 초기화 직후 과도하게 튀지 않는 중·후반 참조 RSI를
많이 사용해 학습 수렴을 빠르게 하는 것**이 목표다.

충격을 최소화하는 것 자체가 최종 목적은 아니다. 충격을 줄이는 대신 작은 박스로만
학습하거나 carryWith RSI 대부분을 loco로 대체하면 원래 목적과 달라진다.
작은 충격이 있더라도 학생이 학습할 수 있는 상태라면 사용 가능성을 검토한다.

- 목표 크기 범위: X/Y 40~65cm, Z 25~55cm. 최대 조합은 65×65×55cm.
- 크기를 먼저 결정하고, 해당 크기·행동에서 쓸 만한 참조 모션 시점을 선택한다.
- 후보가 부족하다는 이유로 작은 박스를 재추첨하지 않는다.
- 정책 학습에 distill weight·KL·teacher rollout 상태를 사용하지 않는다.
- teacher는 초기화 후보의 짧은 물리 검사에만 사용한다.
- 후반 샘플 수와 실제 skill/크기 분포를 유지하는 효과까지 포함해 판단한다.

**학습이 빨라졌다는 결과는 아직 없다.** 현재까지는 기하 후보 검사, 짧은 물리 검사,
scratch 학습/평가 실행 확인이다. 충격 감소와 수렴 개선은 별개다.

## 참조 모션과 pth의 역할

RSI는 기존 `tokenhsi/data/dataset_loco_sit_carry_climb.yaml`의 참조 모션에서 사람의
자세·속도와 AMP history를 가져온다. 손 위치도 참조 자세로 결정된다.
pickUp·carryWith·putDown의 박스 위치/회전은 참조 물체 궤적에서 가져온다.
상자 관련 skill은 sit, climb, pickUp, carryWith, putDown 5종이며 loco RSI도 있다.

검사 teacher는 다음 파일이다.

```text
/home/hwanhee/koo_cvpr/stage1_fix/distill_pth/ApproachScenarioStage1RescueAtKLClimb50_00008000.pth
```

ksh의 동일 파일을 로컬로 복사했다. SHA256:
`8fbefc350cb45edacf21e9323f55759d5ff59b2b1b6d19883f3a2bb8650b0d54`.
teacher는 초기화 이후 action 계산에만 사용했다. teacher에서 도달한 상태를 RSI pool로
저장한 것이 아니다. teacher 저장 메타데이터는 3물체/rescue, 검사 대상은 4물체이며,
probe에서만 모델 strict load와 메타데이터 계약을 분리했다. 전달받은 90% 이상 성공률은
현재 대상 환경에서 재검증하지 않았다.

## 좌표와 속도 초기화 문제

X/Y/Z는 박스 로컬 좌표의 전체 변 길이다. 해당 운반 참조 모션에서는 X가 주로 양손 사이
방향, Y가 깊이, Z가 높이에 해당한다. 박스가 회전하면 세계 좌표상의 방향도 바뀐다.
X값 자체가 양손 간격은 아니다.

원본 모션의 양손 X 간격 중앙값은 carryWith 약 49.8cm, pickUp 약 54.2~54.7cm,
putDown 약 53.4cm였다. 손 중심 간격이므로 손 충돌체의 두께까지 고려한 안전 폭이 아니다.

기존 초기화에서는 사람은 참조 속도를 가지지만 박스 속도는 0이었다.
새 opt-in 경로와 impact_sweep은 carry 박스의 참조 선속도·월드 각속도를 복원한다.
바닥 clamp가 적용되는 수직 방향은 속도를 0으로 한다. sit/climb 박스는 정지 초기화한다.

## 첫 구현: 크기별 기하 후보표

252개 크기를 5cm 간격으로 구성하고 참조 모션을 반프레임 간격으로 검사했다.
손·팔·몸통·다리의 구체/캡슐 충돌체와 발 mesh 정점을 사용한다.
어느 충돌체든 박스 안으로 1cm 초과 관통하면 탈락하며, 발 원점 바닥 관통 2cm 초과도
탈락한다. 캡슐 근사는 보수적으로 팽창시킨다. mesh 정점 검사만으로 삼각형 내부 교차나
물리 안정성을 완전히 보장하지 못한다.

**1cm는 이번 후보 필터에 설정한 기하 기준이지 물리 엔진 오류나 학습 불가능 기준이 아니다.**
손만 검사한 것도 아니며, 후보 0이라는 사실만으로 손이 원인이라고 단정할 수 없다.

| pickUp | 252/252 | 68/252 |
| carryWith | 14/252 | 11/252 |

CLIMB 후반은 과거 slow_near_start와 같이 기존 RSI 제외 구간을 넘어 허용한 기준이다.

그보다 큰 박스에도 충격이 작은 상태가 확인돼 이 범위를 최종 설정으로 채택하지 않았다.

## time_late / semantic_late 구현과 짧은 비교

10월 1일 당시 PID 289953의 shared random binding 설정을 기준으로 별도 옵션을 추가했다.
time_late는 CLIMB 선택 시 70%를 안전한 65~98%에서, semantic_late는 70%를
발이 상판에 접근한 참조 시점에서 선택한다. 후자는 정책 rollout 수집이 아니다.
두 방식 모두 크기를 재추첨하지 않지만 skill 전체 후보가 없으면 같은 크기의 loco로
대체한다. 실제 기본 구현은 **CLIMB만 70% 편향**이며, 모든 skill 100% 후반 편향은

- 후보표의 1cm 필터와 후보 부족 loco 대체는 적용하지 않음. 기존 장면 배치 검사는 유지.

### 진단 지표의 정확한 뜻

`Δv = ||v(t) - v(t-1)||`이며 방향 변화도 포함하는 박스 선속도 벡터 차이다.
담당 박스의 첫 2 control step 최대 Δv가 3m/s를 넘으면 초기 충격 진단 초과로 집계한다.
보조 지표는 전체 20step의 박스 최대 속력이 5m/s를 넘었는지다.
최대 각속도와 carry 계열의 참조 박스 위치 이탈도 저장한다.
장면 종료율은 개별 agent의 넘어짐 판정이 아니다.

**3m/s와 5m/s는 임의의 진단 문턱이며 폭발·실패·학습 불가능 판정이 아니다.**
Δv=1m/s도 수직 튕김이나 회전을 동반할 수 있다. 초과율 0을 '안 튄다'로 표현하지 않는다.

## carryWith 80~90%가 왜 튀는가

참조 모션은 `B20_-_walk_with_box`, 129프레임·30fps·약 4.27초다.
80~90%는 3.41~3.84초의 박스를 들고 걷는 구간이며, 학습 진행률이 아니다.
이 구간은 참조 속도나 각속도가 유독 크거나 급회전하는 구간은 아니었다.

50×50cm에서 높이를 고정한 첫2step Δv>3m/s 비교:

| Z | 80~90% | 90~98% |
|---|---:|---:|
| 25cm | 21/33 (63.6%) | 0/29 |
| 35cm | 28/51 (54.9%) | 0/32 |
| 40cm | 0/34 | 0/29 |
| 45cm | 0/31 | 0/26 |
| 55cm | 7/34 (20.6%) | 0/34 |

정적 기하 비교에서 50×50×35cm의 80~90%는 몸통/골반 관통이 90~98%보다 깊었다.
하지만 높이 40~45cm는 관통이 더 깊어도 큰 Δv가 없었다.
**원인은 아직 확정하지 않았다.** 보행 자세×박스 형상×접촉 위치/방향×정책 첫 행동의
상호작용을 의심할 수 있으나, 현재 기록에는 부위별 첫 substep 충격이 없다.
80~90%가 모든 크기에서 항상 어려운 구간이라고 단정하지 않는다.

## 제안된 샘플링 기준과 미완료 작업

아래는 후속 파일럿을 위한 **미검증 제안**이며 아직 학습 sampler에 적용하지 않았다.

| 첫2step 최대 Δv | 제안 |
|---|---|
| ≤1m/s | 우선 후보 |
| 1~2m/s | 수직 튕김·급회전·박스 이탈·사람 상태 확인 후 조건부 허용 |
| 2~3m/s | 첫 파일럿에서는 제외, 별도 확인 |
| >3m/s | 우선 제외 |

크기→skill→원본 motion ID/시점별 충격을 평가해, 그 크기의 낮은 충격 후반 후보에
높은 확률을 주는 방향이다. 해당 시점의 **원본 상태로 초기화**하며 teacher가 회복한
rollout 상태를 초기화 pool로 사용하지 않는다. 후보가 부족하면 같은 크기·skill의
시점을 앞쪽으로 확장하고, 작은 크기로 재추첨하는 해법은 피한다.

남은 작업:

1. 기존 결과를 Δv 1/2/3m/s 기준으로 다시 분류. 수직 속도·높이 변화·회전·파지 이탈도 검사.
2. size×skill×motion×phase별 표본을 보강하고 다른 seed에서 재검사.
3. 초기 자세 유지 제어와 teacher 제어를 대조. 해당 대조 검사는 아직 구현/실행하지 않음.
4. scratch 학생에서 후보 안정성을 확인. teacher의 회복 능력에만 의존하지 않음.
5. 검증된 물리 충격 후보표를 학습 reset sampler에 연결. 현재 impact_sweep은 기록만 수행.
6. 같은 목표 크기·과제 분포로 기준 RSI와 비교해 성공률 도달 학습 frame·벽시계 시간 측정.
   실제 skill 초기 비율·크기별 후보 부족·후반 다양성·조기 종료를 함께 기록.

충격을 최소화한 설정을 고르는 대신 **크기/후반 상태의 학습 범위를 유지하면서 목표 성공률에
더 빨리 도달하는 설정**을 선택해야 한다. 추가 자세 보정은 큰 크기의 물리 후보가 실제로
부족하다고 확인될 때 검토하며, 기하 후보 0만으로 필수라고 단정하지 않는다.
