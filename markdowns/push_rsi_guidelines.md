# 앞으로 PUSH RSI를 구성할 때의 기준

PUSH RSI의 기본 출발점은 **원본 모션을 손대지 않고, 손 중점≤1m인 실제 밀기 자세 구간만 선별하는 방식**이다. loco 접근 시작은 별도로 유지한다. 이 문서는 2026-10-20에 GPU6에서 실행 중인 두 `_phase` 설정을 코드·YAML과 대조해 정리한 기준이다. 다른 물성/상자/모션을 연구하는 경우 달라진 조건을 별도 설정에 기록하고 다시 검증한다. 사용자의 명시적 변경 지시가 우선한다.

## 1. 원본 자세를 보존한다

- `rsi_retarget: none`, `rsi_sampling: native_size_cache`를 사용한다. 어깨/팔 관절을 돌려 손을 보상 목표0.8m나1.0m에 강제로 맞추지 않는다.
- 원본 DOF position과 velocity를 보존한다. 박스에 맞춘 전체 사람의 yaw/XY 이동, collider 안전 후퇴, 바닥 관통을 없애는 최소한의 전체 Z 이동은 허용한다. 몸을 띄우거나 숙여 손 높이를 맞추지 않는다. 전체 Z 이동은 몸 전체에 동일하게 적용됐는지 확인하고 이동량을 기록한다.
- 팔을 낮춘 뒤 손을 박스에 재정렬하면 손의 전방 도달거리가 줄어 머리/몸통이 박스 가까이 당겨질 수 있다. 손 높이만 맞는다고 안전한 RSI로 판단하지 않는다.
- 보상 손 목표 높이 `height_m`와 초기 RSI의 높이 상한 `rsi_max_hand_midpoint_height_m`를 구분한다. 목표0.8m 실험도 RSI 손 높이를0.8m로 보정하지 않는다. 이후 정책이 목표에 접근하는 것은 정책의 역할이다.

## 2. 높이와 실제 밀기 자세를 함께 선별한다

**손이 낮다는 이유만으로 준비 자세를 PUSH pool에 넣지 않는다.** 실제로 미는 구간이 남지 않는 클립은 통째로 제외한다. 모든 원본 클립을 유지하려고 조건을 풀거나 팔 내린 프레임으로 대체하지 않는다. 최종 RSI와 AMP 전문가 모션 목록은 서로 다를 수 있다.

현재 기본 선별 조건은 다음과 같다.

| 검사 | 기본 조건 |
| --- | --- |
| 원본 손 중점 높이 | ≤1.0m |
| 안전 배치 후 손 중점 높이 | ≤1.0m; 높이 필터 생성 시1mm 수치 여유 사용 |
| 양손 전방 도달 | 각 손이 같은 쪽 어깨보다 몸통 전방으로≥0.25m |
| 양손 상대 높이 | 각 손이 같은 쪽 어깨보다0.25m 넘게 아래로 처지지 않음 |
| 전방 정의 | 몸통 로컬+X축을 월드 XY 평면에 투영한 방향 |
| 크기 조건 | 현재 선별기는 모든 상자 크기 profile에서 통과한 프레임들의 교집합 사용 |
| 연속 구간 | 조건 통과 구간 양끝에서 각각0.2초 제거 후에도≥0.5초 유지 |
| 잘못된 수치/빈 pool | 제외; 해당 크기의 후보가 비면 실패로 보고 대체 원본 프레임을 쓰지 않음 |

위 양팔 조건은 **자세 판별 기준**이며 물리 접촉의 정답은 아니다. 반드시 스켈레톤을 연속 시간으로 검수한다. 다른 골격/축 정의에는 같은 숫자만 복사하지 말고 전방·어깨·손 body 정의부터 확인한다.

후반 우선 샘플링은 선별 완료 후 적용한다. 현재는 PUSH RSI 선택의70%를 해당 클립의 **남은 유효 프레임 중 마지막30%**에서,30%를 전체 유효 pool에서 뽑는다. 이것을 원본 모션 후반30% 또는 실제 접촉70%라는 뜻으로 해석하지 않는다. 후반 pool에도 제외된 준비/정리 자세가 다시 들어가지 않는지 확인한다.

## 3. loco와 PUSH RSI를 구분한다

- 현재 기본 초기화 비율은 **loco 50% / 선별 PUSH RSI 50%**다. 이는 AMP 전문가의 loco33%/PUSH67% 비율과 별개다.
- loco는 상자에서 떨어져 걸어가는 시작이다. 팔이 내려가 있거나 상자와 멀다고 제외하지 않는다. 현재 사람 root→상자 중심 시작거리는1~5m이며 몸-상자 겹침은 없어야 한다.
- PUSH RSI는 상자 뒤에서 팔을 뻗어 미는 자세다. 팔 내린 준비 자세를 loco 대신 PUSH로 분류하지 않는다.
- 원본 발걸음 중 한 발이 들리는 것은 허용한다. 발목 관절점이 아니라 **실제 발 메시의 발바닥**으로 바닥 간격을 판단한다. 두 발의 높이와 초기 지지 상태를 수치로 남기고, 과도한 부유/바닥 관통은 별도 확인한다. 현재 기준도 양발이 항상 바닥에 닿는 조건은 아니다.

## 4. 실제 상자와 초기 배치를 확인한다

현재 원본 PUSH21모션에는 기록된 상자 궤적이 없다. 원본 사람 모션에 장면 상자를 생성해 정렬하므로, 원본 모션을 보았다는 것만으로 손-상자 접촉이 맞는다고 판단하지 않는다.

학습에 사용할 실제 크기·회전·목표·초기화 경로로 다음을 확인한다.

1. 원본 DOF position/velocity 보존, 몸 전체에 동일한 바닥 Z 보정만 적용됐는지 확인한다.
2. **머리·몸통·손·발을 포함한 실제 collider/mesh**가 상자와 바닥을 관통하지 않는지 검사한다. 머리 joint 중심만 검사하지 않는다. 현재 머리 collider는 joint에서 로컬 Z+0.175m, 반지름0.095m인 sphere다. 다른 asset에서는 해당 asset 정의를 다시 읽는다.
3. 손이 목표 반대편의 올바른 상자 면에 있고, 양손의 면 투영이 범위를 벗어나지 않는지 확인한다. 방향 랜덤화가 있으면 그 분포와 대각선 면 선택도 검사한다.
4. 손-상자 간격·머리-상자 간격·양발 발바닥 높이를 기록한다. 현재 `stand_off_m: 0.06`은 명목 정렬 값이며 안전 후퇴까지 포함한 실제 손중점-면 간격은 약0.08m다. 이것을 손이 이미 힘 접촉하는 상태라고 부르지 않는다.
5. RSI 진행률로 상자를 옮긴 뒤에도 목표까지 남은 거리를 확인한다. 현재 최소0.21m를 유지해 초기 상태가 이미 AT 성공이 되지 않게 한다.

RSI는 reset 때 적용하는 초기 상태다. 매 step 원본 자세로 다시 덮어쓰지 않는다. 손 목표의 월드 좌표가 현재 상자 위치·회전으로 갱신되는 것과 RSI 재적용은 다르다.

## 5. 학습 전 검수와 통과 기록

**PTH 파일 존재, 후보 개수, 손 높이, 짧은 PD 검사 하나만으로 검수를 끝내지 않는다.** 검수 결과에는 다음 자료를 남긴다.

- 선별 cache/manifest: 원본 파일 SHA256, source cache SHA256, 모션별 유지/제외 시간 구간, 크기별 후보 수, 최종 cache SHA256.
- 기하 전수 검사: 실제 배치의 전신 관통·손 면 투영·목표 반대편·손 높이 위반 수와 최소 간격. CPU 복원이면 실제 simulator snapshot과 구분한다.
- 영상: 상자+스켈레톤+실제 발 메시. 남은 각 클립의 시작/중간/끝뿐 아니라 연속 구간도 확인한다. 대표 사례 외에 최소 머리 간격/최대 손 간격/최대 발바닥 높이 사례를 포함한다. static 회전 뷰, 원본 시간의 RSI 자세열, 물리 rollout을 구분해 표기한다.
- 초기 물리 검사: 원본 초기 관절각 PD 유지 등 사용한 제어·시간·표본 수·실패 수를 명시한다. 유한성·초기 낙상/급격한 튐/상자 비정상 이동을 확인한다. simulator 검사는 기존 학습과 별도 프로세스에서 수행하고 기존 학습을 임의 종료/재시작하지 않는다.
- 샘플러 검사: 제외한 프레임이 전체/후반 pool에서 모두 빠졌는지, loco/PUSH 비율·부분 reset·원본 관절/속도가 맞는지 확인한다. 평가 모드가 RSI를 건너뛰는 구현이면 학습 reset 경로 또는 명시적 RSI 적용 경로를 검증한다. 단순 eval의 초기 자세를 RSI로 오인하지 않는다.

현재 구현의0.1초 PD screen 통과는 **짧은 초기 상태 검사**다. 장기 균형·정책 접촉 성공·상자 전도가 해결됐다는 뜻이 아니다. 원본 손 높이≤1m 제한도 전도 방지의 충분조건은 아니다. 새 물성/정책 실험에서 성능을 주장하려면 해당 rollout으로 따로 확인한다.

상자 크기/질량/마찰, asset/collider, reset 정렬, 모션 또는 선별 조건이 바뀌면 기존 cache의 호환성을 검사하고 필요한 cache를 새로 생성한다. CPU 선별기는 기존 cache의 부분집합을 만들 뿐, 바뀐 물리 조건을 새로 검사해 주지 않는다. 기존 cache/YAML/checkpoint를 덮어쓰지 않고, 다른 계약의 checkpoint를 파일 이름만 바꿔 직접 resume하지 않는다.
