# PUSH 초기 충돌 문제와 크기별 RSI 구현 방향

작성: 2026-10-20. **설계 메모이며, 아래 수정은 아직 구현하지 않았다.**

## 1. 현재 문제와 확인 근거

현재 PUSH는 한 변 1.3m·질량 25kg·마찰계수 0.6의 상자를 사용한다. RSI(참조 모션에서 시작 자세를 선택하는 초기화)는 손의 중점을 미는 면 앞에 맞추지만, 머리·몸통·팔 전체의 충돌 형상을 검사하지 않는다.

기존 RSI 후보 11개를 각각 두 방향으로 배치한 **22개 시작 상태**의 별도 물리 진단 결과:

- reset 직후 상자는 수평이며, 바닥 겹침은 수치 오차 수준이었다.
- **22/22에서 머리가 상자와 겹쳤고, 최대 침투 깊이는 10.37cm**였다. 손도 6/22에서 겹쳤으며 최대 5.76cm였다.
- 정책 동작 없이 초기 관절 자세를 유지해도 상자가 튀거나 기울어졌다. 초기 속도를 0으로 만드는 것만으로는 해결되지 않았다.
- 같은 초기 상태에서 머리-상자 충돌만 끈 대조 실험은 1초간 최대 기울기가 약 123.36° → 0.86°로 줄었다.

따라서 이 진단에서 확인된 주요 원인은 **기울어진 상자로 시작하는 것이 아니라, 사람과 상자의 초기 겹침이 첫 물리 스텝에서 해소되며 발생하는 충격**이다. 충돌 비활성화와 사람을 30cm 뒤로 옮긴 실험은 원인 확인용이며 최종 해결책으로 적용하지 않는다.

근거: [진단 요약](../../output_etc/check/push_rsi_tilt_20261020/summary.json), [머리 충돌 대조 실험](../../output_etc/check/push_rsi_tilt_20261020/head_control/report.json). 한 seed의 후보 전수·짧은 headless 진단이며, 학습 중 발생률이나 장기 성능을 측정한 결과는 아니다.

추가 [정밀 분석·비교 영상](stage1_push_rsi_collision_audit.md)에서는 원래 샘플러를 유지한 학습1016명·테스트128명의 RSI 시작을 확인했다. 원본에서 손은 머리보다 충분히 앞에 있었지만 팔 높이 보정 뒤 손의 수평 도달거리가 줄고, 손 기준 재정렬로 몸이 약41~52cm 전진하면서 머리 침투가 발생했다. 원본의 손 비대칭을 주원인으로 해석하지 않는다.

## 2. 적용할 상자·접촉 조건

- 모양은 정육면체로 유지하고, 한 변 길이 `s`는 앞서 논의한 **1.0~1.5m**로 둔다.
- 접촉 기준점은 **지정된 미는 면의 가로·세로 중앙**이다. 바닥 위에 수평으로 놓인 초기 상태에서 높이는 `0.5s`다.
- 미는 면이 로컬 -Y 면이면 기준점의 상자 로컬 좌표는 `(0, -s/2, 0)`이다. 이후 상자의 위치·회전을 따라 변환한다.
- 질량은 크기에 따라 **20~25kg**으로 둔다. 구체적인 매핑은 아래의 선형식을 제안한다. 마찰계수는 0.6을 유지한다.

`m(s) = 20 + 5 × (s - 1.0) / (1.5 - 1.0)` kg

| 한 변 길이 | 초기 접촉 높이 | 제안 질량 |
| --- | --- | --- |
| 1.0m | 0.50m | 20kg |
| 1.25m | 0.625m | 22.5kg |
| 1.5m | 0.75m | 25kg |

이는 일정한 밀도를 사용하는 설정이 아니다. simulator에는 크기별 질량이 위 값이 되도록 밀도 `m(s)/s³`를 적용하고 실제 질량을 확인한다.

## 3. 원본 모션과 새 RSI 캐시의 역할

**원본 `ref_motion.npy`를 새로 만들 필요는 없다. 원본을 보존하고, 이를 보정한 PUSH 전용 RSI 캐시를 새로 만든다.**

현재 원본 NPY에는 사람의 모션이 있으며, 측정된 상자·goal 궤적은 없다. 현재 PUSH bank도 보정된 전체 자세 대신 `motion_id`, `time`, `box_progress` 등을 저장하고, 물성을 1.3m·25kg으로 고정 검사한다. 따라서 YAML이나 기존 bank의 크기 숫자만 바꿔서는 사용할 수 없다.

새 캐시에는 크기별로 보정한 root·관절 상태와 초기 속도·AMP 이력 구성에 필요한 정보를 저장한다. 원본 모션 hash, humanoid 충돌 asset, 크기·질량·마찰·접촉 기준과 보정 버전을 캐시 식별 조건에 포함한다. 기존 과제의 공용 `output/rsi_cache*`와 기존 PUSH bank는 보존한다.

초기 구현은 **5cm 간격의 11가지 크기**를 제안한다. 환경 생성 시 크기를 배정하고 해당 크기의 검증된 캐시를 사용한다. 한 환경의 크기를 매 reset마다 바꾸는 것과 완전한 연속 크기는 별도 구현이 필요하다. 가까운 크기의 캐시를 검증 없이 대입하지 않는다.

## 4. 자세 보정과 검증 순서

1. 원본 PUSH 모션에서 후보 프레임과 초기 AMP 이력용 연속 프레임을 가져온다.
2. 실제 머리·몸통·팔 등의 충돌 형상을 기준으로 사람의 위치를 조정해 상자와의 겹침을 없앤다. 모든 크기에 같은 후퇴 거리를 적용하지 않는다.
3. 팔의 역기구학(IK)으로 양손을 해당 크기의 미는 면 중앙 높이에 맞춘다. 손 중심은 현재 손 충돌 반경 4cm와 여유 간격을 고려해 면 바깥에 둔다. 보상 기준점은 면 위에 유지한다.
4. 보정 후 전신 겹침·관절 범위·손 도달 여부를 다시 검사한다. 불가능한 후보는 제외하며, 특정 크기에 유효 후보가 없으면 이를 명시한다.
5. 관절 상태·속도·PD 목표와 **AMP 초기 10프레임 이력**을 보정된 자세에 맞춰 일관되게 구성한다.
6. 별도 simulator에서 실제 충돌을 켜고 초기 자세 유지 실험으로 튀어 오름·급격한 기울어짐을 검사한 뒤 캐시를 확정한다. 운영 학습의 reset 안에서 추가 물리 스텝을 실행하지 않는다.

접촉 보상의 높이만 바꾸거나 사람만 뒤로 옮기는 수정으로 끝내지 않는다. 원본 모션은 유지하되, RSI 이력과 AMP 참조를 가져오는 경로에 보정이 어떻게 반영되는지도 함께 확인한다. 짧은 초기 안정성 통과는 PUSH 학습 성공을 의미하지 않는다.

## 5. 코드 분기와 구현 범위

| 위치 (`tokenhsi/` 기준) | 필요한 변경 |
| --- | --- |
| `env/tasks/multi_agent/humanoid_ma_stage1_push.py` | 크기·질량별 상자 생성, 고정값 0.65m를 실제 반높이로 교체, 크기에 맞는 RSI 상태 적용 |
| `env/tasks/multi_agent/push_reward.py` | 고정 접촉 높이 0.6175m를 상자 높이의 50% 기준으로 전환 |
| `env/tasks/multi_agent/push_rsi.py` | 고정 높이 팔 보정을 크기별 보정 상태·이력 로딩으로 확장 |
| `utils/stage1_push.py` | 새 캐시 계약 검증과 크기·물성 변경을 명시한 checkpoint 전이 경로 추가 |

별도 PUSH 크기 실험 config·train/test/VNC wrapper와 옵션으로 분리한다. 기존 과제/PUSH 50:50 샘플링, 기존 과제에만 적용하는 teacher KL, 목표 거리·접근 커리큘럼 등은 이번 변경 범위에서 유지한다. 상자 크기는 기존 관측의 꼭짓점 정보에 포함되므로 입력 차원 확장을 전제로 하지 않는다.

기존 checkpoint를 사용할 경우 크기·물성·RSI 계약이 달라지므로 **일반 resume가 아닌 명시적 warm-start 경로**가 필요하다. 현재 전이 검사는 이 변경을 허용하지 않는다. 구현 후 크기별 초기 충돌·질량·접촉점과 짧은 학습/추론 경로를 확인하며, 기존 스킬 보존과 PUSH 성공률은 별도 행동 평가로 판단한다.
