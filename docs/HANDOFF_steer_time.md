# 속도 명령 steering — ma 로 넘기는 것

**한 줄 요약**: 창이 덮는 길이 `M` 이 곧 속도 명령이다. 창은 지금처럼 등간격 6점이고,
`M` 이 짧아지면 천천히 가라는 뜻이다. 보상의 `1.5` 상수가 `M/1.6` 으로 대체된다.

작성 2026-08-20. 구현은 `TokenHSI-steer`, `STEER_MRAND` 뒤에 숨어 있다.
기준 실험은 **`f35_m4`** 다.

---

## 1. 핵심

기존 창은 **길이가 고정**(2.4 m)이고 목표 속도도 **상수**(1.5 m/s)였다.
둘을 하나로 묶는다:

```
M = 창이 덮는 길이         창은 언제나 등간격 6점
v_tar = M / 1.6 s          1.5 m/s 로 2.4 m 를 가는 데 걸리는 시간이 1.6 s
```

| M | 점 간격 | 목표 속도 |
|---|---|---|
| 2.4 m | 0.40 m | 1.50 m/s |
| 1.8 m | 0.30 m | 1.125 m/s |
| 1.2 m | 0.20 m | 0.75 m/s |
| 0.6 m | 0.10 m | 0.375 m/s |
| 0 | 0 | 정지 |

**공간 지평이 아니라 시간 지평이 고정된다.** 창은 항상 1.6 초 앞을 보여주고,
느리게 갈 때 공간적으로 짧아질 뿐이다.

**월드모델 입장에서는 등간격 6점을 주는 것이 전부다.** 간격을 줄이면 느려진다.

---

## 2. 원본 TokenHSI 에서 바뀌는 것

```python
# 관측 — 형태 동일, 길이만 M
창 = path[s + (M/6)·i],  i=1..6        s = 단조 호길이 래칫
     to_local(창, root_xy, heading)     지금과 같은 root yaw 프레임

# 보상 — 두 줄
v_tar = M / 1.6                         원본은 1.5 상수
u     = normalize(path[s + M/2] - xy)   원본은 s + 1.2 고정
vel   = exp(-5*(v_tar - u·v)^2)         모양 동일
```

`pos_near` · `handheld_r` · `putdown_r` · `power` · 계수 · exp 모양 · 핀은 **전부 원본 그대로**.
`v_tar = 0` 이면 along-track 투영이 의미를 잃으므로 `exp(-5*|v|^2)` 로 degenerate 시킨다 —
"아무 방향으로도 움직이지 마라" 가 곧 정지다.

**자기교정이 공짜로 남는다.** 창이 내 투영 기준이라 지연이 쌓이지 않는다.
시계·재anchor 주기·집기 핀 같은 장치가 전혀 필요 없다.

---

## 3. GT 를 어떻게 뽑나 — 여기가 유일한 설계 결정

```python
M(s) = 2.4 * r(s)
r(s) = 경로를 n 등분해 구간마다 {1.0, 0.75, 0.5, 0.25} 중 하나
```

에피소드 시작에 한 번 뽑고, 몸이 그 구간을 지나는 동안 고정이다.
스텝마다 바뀌지 않는다 — 4 구간이면 전환이 대략 3 초에 한 번.

> **`r` 을 곡률의 함수로 두면 안 된다.** 경로 모양에 묶으면 정책이
> "커브가 보이니 느리게" 로 보상을 만족시키고 **간격 읽는 것을 영영 배우지 않는다.**
> 배포에서 필요한 건 정반대다 — 직선에서 "다른 에이전트가 지나가니 반속" 을 듣는 것.
> 커브에서 느리게 갈지는 **월드모델이 판단할 일**이지 steer 가 알 바가 아니다.

---

## 4. 왜 이 방향인가 — 참조 모션 속도 분포 (실측 10,281 프레임)

| 속도 | 비중 |
|---|---|
| 0~0.3 m/s | **43.3 %** |
| 0.3~0.6 | 21.3 % |
| 0.6~0.9 | 16.2 % |
| 0.9~1.2 | 14.8 % |
| **1.2~1.6** | **4.4 %** |
| 1.6 이상 | 0.0 % |

중앙값 **0.36 m/s**. **지금 명령하는 1.5 m/s 는 데이터 상위 4 % 이고 1.6 을 넘는 프레임은 없다.**

세 가지가 이걸로 설명된다 — 뷰어에서 "다리만 성큼성큼 억지로 걷는" 것,
AMP 판별률 99.5 %, 커브에서 이탈이 커지는 것. **모션 프라이어에 없는 걸음을
만들어내고 있었다.** 느린 명령은 오히려 데이터가 훨씬 두텁다.

## 5. 지표 — success / app_xt 로는 안 보인다

경로를 완벽히 따라가면서 명령 속도를 무시할 수 있다. `app_xt` 는 그걸 못 본다.

```
spd_err = |실제 속도 - v_tar|       ← 새 주 지표
```

npz 에 `cmdv`(명령 속도)와 `actv`(실제 속도)를 프레임마다 남긴다.

**배달 실패의 원인이 둘이라 분리해야 한다** — 명령을 못 들어서인지, 느린 명령 때문에
20 초 안에 못 끝냈는지. 경로 11.4 m 를 1.5 로 가면 7.6 초인데 배수를 랜덤으로 뽑으면
평균 12 초다. `cmdv` 의 에피소드 평균을 같이 보면 갈린다.

## 9. 부록 — 시간 인덱스 (다른 접근, 보류)

절대 타이밍("t=5 s 에 여기")이 필요하면 창을 호길이가 아니라 **시각**으로 인덱싱하는
방법이 따로 구현돼 있다 (`STEER_TIME=1`, `build_tau`). 정지의 **지속 시간**까지
명령할 수 있는 대신 자기교정을 잃어 지연이 누적된다.

**협동 회피에는 필요 없다고 판단했다** — "B 가 지나갈 때까지 대기" 는 절대 시각이 아니라
리플랜으로 표현된다. 다음 계획에서 `M` 이 다시 올라가면 출발한다.

`f30_t_c20`(구현 검증)과 `f32_stop1`(정지 지속시간)이 근거로 남아 있다.
