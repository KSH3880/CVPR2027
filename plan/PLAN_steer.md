# steer 계획

목표는 pretrained Carry 성능을 유지하면서 외부 steering input으로
approach → grasp → carry → placement 전 구간의 이동 경로를 조종하는 것이다.

공통 실험 설계와 GPU 배치는 [전체 PLAN](PLAN.md), 완료 수치는
[AUTO_RESULTS](../experiments/AUTO_RESULTS_steer.md), 검토된 결론은
[EXPERIMENTS](../experiments/EXPERIMENTS_steer.md)를 따른다.

## 현재 기준 설정

| 항목 | 값 |
|---|---|
| 에이전트 | A=1, Carry |
| 환경 | 4,096 env |
| 간격 | `STEER_ENVSPACING=5`, `STEER_CELL=60` |
| 접촉 버퍼 | 4 M |
| 경로 | `STEER_TRAJ=v3`, curvature 0.15 |
| 조종 | `latpen`, `c=2.0`, `STEER_VEL=aim` |
| 관측 | phase-free, `STEER_DUAL=1`, K=6, 조준 거리 1.2 m |
| 기준 체크포인트 | [`f22_long_c20` 11,000 iter](../TokenHSI-steer/output/steer/f22_long_c20/Humanoid_18-10-39-37/nn/Humanoid_00011000.pth) |
| 성공률 | **0.9336** |
| 접근 경로 이탈 중앙값 | **0.0993 m** |
| 운반 경로 이탈 중앙값 | **0.0359 m** |
| 평가 원장 | `f22_long_c20_e11000` in `runs/queue/results.tsv` |

이 체크포인트를 현재 비교·재현 기준으로 쓴다. 다만 `c`와 학습 이터의 최종 설계 결론은
장기 구간 비교가 끝나기 전까지 열어 둔다.

### 간격·버퍼가 `5 / 4 M` 인 이유 (2026-08-18 확정)

**새로 시작하는 런은 전부 `STEER_ENVSPACING=5`, `max_gpu_contact_pairs=4 M` 을 쓴다.**
lab 트랙 A~E 축의 결론이고 근거는 [ENV_SCALING §9](../docs/ENV_SCALING.md).

| | 값 | 근거 |
|---|---|---|
| `envSpacing` | **5** | `0` 이면 env 원점이 전부 겹쳐 안 쓰는 플랫폼 8,192 장이 한 점에 주차되고, 접촉쌍 요구량이 22.6 M 으로 뛴다. 5 면 요구량이 16384 env 에서도 0.3 M 이다 |
| 접촉 버퍼 | **4 M** | 실측 요구량의 13 배 여유. 버퍼는 작을수록 빠르다 (32 M 대비 sfps +8.7 %). env 수와 무관하게 하나로 통일해 `num_envs` 를 바꿀 때 같이 계산할 항목을 줄인다 |

**이게 지금까지 잰 것 중 최선이라 이걸로 간다.** 다만 학습 중립성은 `f18c_sp5`(n=1) 하나뿐이고
성공률이 −2 σ 라 "같다"고 증명된 상태는 아니다 — 효과가 있어도 작다는 정도까지만 말할 수 있다.

> **그래서 옛 런과 직접 비교할 때는 씬을 맞춰야 한다.** `f11`~`f23` 은 전부 `0 / 32 M`
> 에서 학습됐다. `f30`~`f32`(시간 인덱스)가 회귀 대상 `f23_c20_b` 와 같은 씬을 쓰려고
> `f30`~`f32` 는 새 계열이라 씬을 맞추지 않고 5 / 4 M 을 그대로 쓴다. 대신 1 단계
> 회귀의 판정선을 씬 차이만큼(성공률 0.012, 이탈 0.024) 넓혀서 읽는다.

## 활성 큐

사용자는 `tag`, 질문, 환경변수와 행 순서를 관리한다. 자동화는 3열 `상태/GPU`와 완료 행만 관리한다.
envSpacing은 `STEER_ENVSPACING`을 사용하며 `STEER_SPACING`은 금지한다.
기본은 `f11_long`, 6000 iter, v3·latpen(`c=1.2`)·dual·aim·K=6과
4096 env / spacing 5 / contact 4M이다. 4열에는 이 기본과 다른 값만 적는다.

> **f30~f32 는 base_env 그대로 `envSpacing 5 / 4 M` 을 쓴다.** 새 계열이라 옛 런과
> 씬을 맞출 이유가 없다. 다만 1 단계 회귀 대상 `f23_c20_b`(0.8730 / 0.1142)는
> `0 / 32 M` 에서 학습됐으므로 씬 차이가 섞인다 — 그 크기는 `f18c_sp5` 로 실측했고
> 성공률 −2 σ(0.012), 이탈 +1 σ(0.024) 다. **판정선을 그만큼 넓혀서 본다**:
> 성공률 0.85 이상, 이탈 0.14 이하면 구현이 맞은 것으로 본다.
>
> **`STEER_SPACING` 금지** (창 점 간격과 이름 충돌). envSpacing 은 `STEER_ENVSPACING`.
>
> **f30~f32 는 시간 인덱스 계열.** τ[t] 를 시간축으로 재샘플하므로 점 간격이 곧 속도고,
> 보상의 1.5 상수가 `‖v_cmd‖` 로 대체된다. 관측 폭이 2K+2=14 라 기존 체크포인트를 재개할
> 수 없다 — `ckpt_stage1` 에서 새로 학습하고 비교 대상은 `f23_c20_b` 다.

> **한 번에 3 개만 돌린다.** 나머지 후보는 1 단계가 통과한 뒤에 넣는다:
> `f30_t_c10`(c=1.0) · `f30_t_c05`(c=0.5) · `f31_vk060`(g=0.6) · `f32_stop2`(정지 2회).
>
> **집기 핀(`STEER_GRABPIN=0.5`)이 기본으로 켜져 있다.** τ 의 시계가 "박스 0.5 m 안 &&
> 아직 안 들었음" 동안 멈춘다. GT 에 미리 박는 정지가 아니라 매 스텝 몸 위치로 판정하므로,
> 일찍 도착하든 늦게 도착하든 실제로 닿았을 때 멈춘다. 이동 타이밍은 τ 가 명령하고
> 조작 타이밍은 핀이 반응한다.

## 판정 기준

- 모든 학습 행은 최종 평가와 `results.tsv` 기록까지 성공해야 완료된다.
- 성공률과 접근·운반 경로 이탈을 함께 본다.
- 학습 보상과 AMP 판별자 점수로 우열을 정하지 않는다.
- 구조적으로 0이 되는 평가 repeat 1은 비교에서 제외한다.
- 성공률 차이가 시드 노이즈 바닥 안이면 이탈 개선만으로 전체 우승을 선언하지 않는다.
- 경로·환경 설정이 학습 시점과 평가 시점에 같은지 먼저 확인한다.

## 열린 질문

1. DUAL의 이탈 개선이 성공률 손실을 감수할 만큼 필요한가.
2. 25,000 iter 구간에서는 어느 c가 성공률·이탈의 무릎인가.
3. 급커브 이탈을 현재 정책으로 감수할지 별도 속도 설계가 필요한가.
4. adapter 재학습에서 생긴 원본 대비 성공률 손실이 장기 학습으로 회복되는가.
