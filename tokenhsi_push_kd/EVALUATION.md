# 평가 기준 — 최종 요청

기존 SIT/CARRY/CLIMB는 **원본 TokenHSI의 각 과제 eval 기준**으로 평가한다. 원본 teacher와 학습 student에 같은 조건을 적용하고, 각 과제의 teacher 대비 상대 성능 하락이 5% 이내인지 확인한다. TRAJ는 제외한다.

PUSH는 **우리 PUSH 목표 영역 기준 final 성공률 >85%**를 목표로 한다. 동일 checkpoint가 기존 세 과제 보존 조건도 만족해야 한다.

| 지표 | 정의 | 용도 |
| --- | --- | --- |
| final | 각 표본의 첫 에피소드 종료 시점에 목표 영역 조건을 만족 | 목표 85% 초과의 주 지표 |
| ever | 같은 첫 에피소드 중 한 번이라도 목표 영역 조건을 만족 | 함께 제출하고 발표 자료에 포함할 보조 지표 |

final과 ever에 동일한 공간 판정을 사용한다. final은 종료 시점 판정이며, 별도의 연속 유지 시간 조건은 추가하지 않는다. ever가 85%를 넘더라도 final이 목표에 미달하면 목표 달성으로 보고하지 않는다. seed별 두 성공률·표본 수·낙상률·종료 잔여 거리를 함께 보고한다.

## 우리 영역 판정과 이관 코드의 차이

현재 우리 정식 평가의 `evaluation_protocol.spatial_success`는 PUSH에서 상자 중심과 목표의 **3D 거리 ≤20cm**를 목표 영역 판정으로 사용한다. PUSH에서는 point/region 판정이 동일하다. 이번 기준은 그 공간 판정을 final/ever에 적용하는 것이다. 보상용 CONTACT gate나 손 접촉 여부를 성공 조건으로 추가하지 않는다.

반면 이관본의 `tokenhsi/learning/push_kd_player.py`는 참조 환경의 native reward success를 받아 final/ever를 기록한다. 해당 기준에는 거리20cm와 높이오차1mm가 포함돼 있으므로, **현재 이관 eval을 그대로 실행한 수치가 요청한 우리 영역 기준의 수치라고 간주하면 안 된다.** 인턴 실험에는 평가 어댑터를 점검하고 우리 영역 판정으로 맞추는 작업을 포함한다. 학습 reward·물성·AMP·RSI는 변경하지 않는다. 기존 native 결과를 함께 보존할 경우 지표 이름을 구분한다.

영역 판정은 물리 상자 중심/목표 좌표에서 독립적으로 계산하고, 첫 에피소드 종료 시점 수집·부분 reset에 따른 이력 초기화·낙상 시 종료 처리도 점검한다. 새 에피소드의 성공이나 낙상 후 움직임을 이전 에피소드에 섞지 않는다. 평가 변경 코드와 seed별 원본 결과를 제출하여 요청자가 동일 checkpoint를 재평가할 수 있어야 한다.

시작 조건은 제공한 loco-only, 2인·4상자 PUSH 장면을 유지한다. final이라는 시간 집계 기준을 적용하기 위해 장면 구성을 바꾸거나 우리 모델의 정책을 사용하지 않는다. Seed 목록·표본 수·validation/test 분리는 결과를 보기 전에 고정하고 제출 문서에 남긴다.

이 문서는 평가 요구사항이다. 이관 작업에서는 영역 평가 어댑터를 새로 구현하거나 GPU 평가를 실행하지 않았다. 기존 eval 명령은 baseline 동작 확인용이며 최종 목표 판정에는 위 정렬 작업이 필요하다.
