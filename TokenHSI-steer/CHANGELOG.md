### 전 구간 경로로 전환 + 보상 계수 버그 수정 (F0)

S계열은 운반 구간만 조종했다. 사용자 지시로 approach→grasp→carry→placement 전 구간으로
확장하고, 옛 정의로 돌던 학습런 6개를 중단했다.

- 경로: 사람→박스→목표를 지나는 사인급수 곡선. sin이 양 끝에서 0이라 세 점을 정확히 지난다.
  턴 제한 없음 — 박스에서 멈추므로 코너는 공짜. 저장 버퍼 12.8 m → 32 m (실측 최대 20 m).
- 위상 전환: 픽업 전 root를 접근 leg에, 후 box를 운반 leg에 투영. **leg 마스킹 필수** —
  경로가 박스에서 되접히므로 안 하면 운반 중 호길이가 거꾸로 간다. 검증 24/24, 역주행 0/24.
- **보상 계수 0.4 → 0.2**: 네이티브 속도 항이 각 보상 안에서 0.1인데 2.0배 스케일이므로
  방향 교체 비용은 0.2다. S5까지 0.4를 써서 교체가 아니라 순증이었다. D>B>C 순위 재확인 필요.
- **npz 스냅샷 desync 수정**: 경로를 dump 시점에 통째로 저장해 나중 에피소드 경로가 앞
  궤적과 짝지어졌다. 이것 때문에 접근 검증이 3/19로 나와 env를 의심했지만, 계측 결과
  리셋 시점 root/box/target 이동은 전부 0.000 — 분석기가 틀렸다. 로그가 열려 있을 때만
  경로를 스냅샷하도록 바꿔 구조적으로 못 어긋나게 했다. 고친 뒤 24/24 통과.

### 조준점 pos 항 추가 (STEER_POS) + 핀에 대한 오해 정정

조준점 vel 만으로는 이탈 압력이 약하다고 보고, 같은 조준점을 목표로 하는 pos 항을
원본 TokenHSI 꼴(`exp(-0.5*err)` + 핀)로 추가했다. `STEER_POS=off|aim|lat`, 계수
`STEER_POS_C` 기본 0.1.

- **핀은 처음부터 문제가 아니었다.** "각 항은 자기 목표까지의 거리로 핀을 판정한다"고
  잘못 가정해서 `L_eff` 같은 보정을 설계했는데, 원본의 `dist_mask`는 항별 속성이 아니라
  과제 상태(박스 도착 / 타겟 도착)다. 조준점을 몇 개 얹든 핀은 `pin_walk`/`pin_carry`
  두 개 그대로다. 그 보정은 폐기했다.
- **실제로 남은 차이는 감도 하나뿐.** `d² = L² + lat²` 라 조준점까지 거리는 `L`에 눌린다.
  1 m 이탈에 aim 은 0.487→0.295 (폭 0.19), lat 은 1.000→0.607 (폭 0.39). 즉 aim 은
  원본 pos 감도의 절반이다. `L`을 줄이면 연속적으로 lat 에 수렴하므로(L=0.6 이면 폭 0.33)
  둘은 같은 축의 두 점이지 다른 설계가 아니다.
- `lat` 쪽은 walk 가 `lat_root`, carry 가 `lat_box` 를 쓰므로 위상 없는 경로에 마지막으로
  남아 있던 `held` 불리언이 사라진다. 기존 xtrack(항 밖 벌점, 계수 −2.0, 핀 없음)과는
  형태가 다르다.
- 순증 항이라 보상 천장이 1.6 → 2.0 이 된다. 수익률로는 대조군과 비교 불가이므로
  성공률·추종 이탈로만 판정한다. `STEER_PF_VERIFY` 는 이 항을 끄고 교체 항등식만 검증한다.

큐 선두에 v2 위 4슬롯: `f4_base`(대조군) / `f4_pos_aim` / `f4_pos_lat` / `f4_xtrack`.
v1이 아니라 v2 위에 올린 이유는 v1에서는 대조군 이탈이 0.168 로 조종군과 잘 안 갈렸기
때문이다 — 거기서 뽑은 승자가 v2로 전이된다는 보장이 없다.

### 평가가 학습 설정을 재현하지 않았다 — F3 L 축 5개 무효, 재측정

`f3_K3` 평가가 형상 불일치로 죽으면서 드러났다. 평가는 체크포인트를 **새로 만든 env** 에
올리는데, 학습 때 쓴 설정을 재현하지 않으면 그 자리를 **그 시점의 기본값**이 채운다.
`STEER_K=3` 은 6차원 vs 12차원으로 즉사해서 바로 보였지만, 같은 구멍의 **조용한 쪽**이
훨씬 비쌌다 — 21:25 에 `STEER_TRAJ` 기본값을 v1→v2 로 바꾼 뒤 시작된 평가 5개가
**v1 으로 학습한 정책을 v2 경로에서 채점**했다.

npz 에 저장된 경로의 leg1 부호전환 수로 판정했다 (v1 은 모드 3 이라 평균 1.0 이상,
v2 는 한 혹이라 0.2 근처). `f3_base` 만 1.19 로 정상이었고 나머지 다섯은 0.18~0.43 이었다.
다시 재니 성공률이 0.02 이상 움직였고 (L0.6 0.8955→0.9180, L1.0 0.9062→0.9258),
그 값으로 내렸던 판정 두 개가 **둘 다 틀린 것으로 드러났다**:

- "조준거리 1.2 가 최적, 양쪽으로 나빠진다" → 실제로는 0.6~1.5 에서 두 지표를 다 이기는
  값이 없다. v1 경로가 거의 직선이라 이 축이 애초에 안 재진다.
- "위상 없는 베이스에서 xtrack 은 접근에 무효" → 실제로는 0.155→0.126 (−19%), 운반은
  0.074→0.048 (−35%), 성공률 손해는 노이즈 이하. **xtrack 은 어느 베이스에서든
  0.126~0.127 바닥을 만들고, 위상 제거와 합쳐지지 않는다** — 같은 것을 고치고 있다.

**막은 방법**: `launch()` 가 학습 시작 시 `runs/queue/logs/<tag>.env` 에 그 런의 전체 설정을
적고 `eval_one.sh` 가 그걸 source 한다. 사이드카가 없으면 **추측하지 않고 거부한다**(exit 5).
이미 돌던 14개 런은 소급 생성했다. 기본값을 바꾸는 것이 과거 런의 채점을 조용히 바꾸는
경로가 이걸로 닫혔다.

교훈은 "기본값 바꿀 때 조심하자" 가 아니다 — 그건 이미 알고 있었고 그래서 틀렸다.
**평가가 학습을 재현한다는 것을 구조가 보장해야 한다.**

### F5 — 보상이 추종에 평평하다는 것을 찾았다. F4 전체가 여기서 무효화된다

같은 설정을 4번 학습했더니 접근 이탈이 0.124 / 0.161 / 0.238 / 0.250 으로 갈렸다.
설정은 사이드카로 확인해 글자 하나까지 같고, 평가는 각 4회 반복해 ±0.004 다.
**학습런 간 변동 0.060 — 평가 변동의 15배.**

수렴 문제가 아니었다. 네 런의 학습 보상이 615~622 (1% 안), 에피소드 길이도 578~581 로
전부 같다. **똑같이 잘 학습됐는데 우리가 재는 지표만 2배 갈린다.**

계산해보니 원인이 분명했다. 이탈이 0.125→0.251 로 두 배 나빠질 때 에피소드 전체
보상 손해가 **조준점 속도항으로는 1.09** 인데, 관측된 런 간 보상 변동이 6.2 다.
**최적화 대상이 노이즈보다 6배 작다.** SGD 가 그 방향으로 학습할 수가 없고, 그래서
네 런이 같은 보상을 받고 서로 다른 행동에 착지한다. 베이스가 두 덩어리로 갈리는
모양(0.124·0.161 / 0.238·0.250)이 그 증거다.

xtrack 은 이 진단이 예측한 대로 움직인다 — 신호가 10.2 로 노이즈를 넘는다:

| | 학습런 4개 평균 | 시드 표준편차 |
|---|---|---|
| f5_base | 0.1934 | 0.0605 |
| f5_xt   | 0.1217 | 0.0235 |

평균을 낮출 뿐 아니라 **시드 변동을 2.6배 줄인다.** 평균 차이는 t=2.21 로 시사적이고,
분산 축소 쪽이 더 강한 증거다.

**결과적으로 F4 16칸의 축 판정이 전부 무효다.** L·K·꺾임 상한의 차이(0.129~0.243)가
베이스 한 설정의 시드 변동(0.124~0.250) 안에 들어간다. 보상이 평평한 상태에서 축을
돌렸으니 측정이 성립하지 않았다. 하루 동안 축을 여섯 개 돌렸는데 **재고 있던 것이
축이 아니라 착지점 난수였다.**

### 경로 v3 확정 — 모양 인자 넷, 서로 독립

사용자가 원한 인자는 넷이었다: 높이 · 좌우 위치 · 퍼짐 · S자 확률. 그런데 내가 얹은
**꺾임 상한이 이들을 묶고 있었다** — 상한은 모양을 바꾸는 게 아니라 넘는 경로의 높이를
깎으므로, 퍼짐을 내리면 높이도 따라 내려갔다. 상한을 빼고 넷만 남겼다.

```
STEER_TRAJ=v3
  높이       0 ~ 2.2 m        진짜 필요치(협동 회피 ~1.2 m)의 2배 여유
  좌우 위치  ±0.8             |c|<1 이 혹 하나를 보장하는 조건
  퍼짐       0.85 ~ 1.8       |sin|^p. 0.85 미만은 양 끝 기울기가 발산한다
  S자        0.1
  꺾임 상한  없음
```

`f(t) = |sin(m·pi·t)|^p · sign(sin) · (1 + c·cos(m·pi·t))` 를 max 로 정규화한 뒤 높이를
곱하므로 **퍼짐을 바꿔도 봉우리 최고점은 뽑은 진폭 그대로**다. 테스트가 이 불변량을
직접 검사한다 (진폭을 고정해야 비교가 성립한다 — 퍼짐이 난수를 하나 더 소비해서,
같은 seed 라도 범위를 주면 진폭 추첨 자체가 달라진다. 처음 쓴 테스트가 이걸 놓쳐서
"높이가 1.8 m 변했다"는 가짜 실패를 냈다).

**v2 의 기본값을 바꾸지 않고 v3 라는 별도 이름으로 넣었다.** 기본값을 바꾸면 끝난 런의
재평가가 조용히 달라진다 — v1→v2 때 그렇게 다섯 런을 잘못 채점했다.
